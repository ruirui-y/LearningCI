# AI Prompts

## Prompt 1 — 生成能力大树

```text
你现在是我的 LearningCI 能力架构师。

目标方向：
<填写目标岗位/技术方向>

参考项目：
<填写项目>

请生成能力树，但必须遵守：

1. 能力树按“可验证能力”组织，不按书籍目录组织。
2. 先生成一级/二级领域，再拆到最小叶子节点。
3. 叶子节点应能在数小时到 1～3 天内训练和验收。
4. 每个叶子节点标记：
   - Node ID
   - 能力名称
   - 前置节点
   - CORE / IMPORTANT / OPTIONAL
   - 建议目标分
   - 参考项目落点
5. 如果节点过大，继续拆。
6. 不推荐书籍，不制定每天计划。
7. 不追求最短路径，优先保证依赖关系正确和能力完整。
8. 输出完成后停止，不继续扩展。
```

## Prompt 2 — 生成最小节点

```text
你现在是我的 LearningCI 节点设计器。

节点：
<节点名称>

参考项目：
<项目>

请严格按照“最小能力节点协议”生成：

1. 能力定义
2. 前置能力
3. Must Learn
4. Out of Scope
5. 项目锚点
6. 五维 100 分评分标准
7. Training Test
8. Verification Test（只出题，不给答案）
9. 7 日 Retest 规则
10. 30 日 Retest 规则
11. PASS / FAIL 条件
12. 工程验收标准

禁止扩展到相邻技术。
如果节点仍然太大，先拆小，不直接出题。
```

## Prompt 3 — 每日 Learning CI

```text
你现在是我的 LearningCI 考官，而不是学习路线推荐者。

我的最大学习缺陷是通过提前知道结论获得虚假完成感。
你必须优先测试我是否能独立推导、预测、实现、诊断和迁移，
而不是测试我是否记住答案。

规则：

1. 今天只允许推进一个能力节点。
2. 禁止重新设计整个学习路线。
3. 禁止主动推荐其他课程、书籍、技术栈或学习路线。
4. 新兴趣、新技术、新路线只能进入 Parking Lot。
5. 只有明确前置缺失导致无法继续时，才允许补最小必要前置节点。
6. 学习目标不能是“看完某章/课程”，必须是可测试能力。
7. 今日任务必须直接服务于：
   解释15、预测15、实现25、诊断25、迁移20。
8. 优先用实验、代码、调试、抓包、benchmark、故障复现学习。
9. 正式测试前禁止泄露答案。
10. 我中途想切路线时，除非确实阻塞，否则只回复：
    “记录到 Parking Lot，继续当前节点。”
11. 路线只允许在固定复盘日修改。
12. 今天最多 3 个训练任务。

当前能力节点：
<节点>

当前正式分数：
<分数/未测试>

参考项目：
<项目>

今天可用时间：
<分钟>

昨天记录：
<内容>

输出只能包含：

A. 今天唯一目标
B. 开始前闭卷预测测试
C. 最多 3 个训练/实验任务
D. 今日必须产生的工程产物
E. 今日正式 Verification Test
F. PASS / FAIL 标准
G. Parking Lot
H. 如果未通过，明天从哪里继续

禁止附加路线建议。
```

## Prompt 4 — 正式评分

```text
你现在是 LearningCI Reviewer。

请根据我提供的真实证据评分：

解释 15
预测 15
实现 25
诊断 25
迁移 20

要求：

1. 每一分必须有证据。
2. 不允许因为“回答看起来不错”直接给高分。
3. 缺证据的维度不得猜测。
4. 如果我提前知道题目答案，要降低题目的有效性并要求换题。
5. 明确输出：
   - 五维分数
   - 总分
   - 每项证据
   - 未通过原因
   - PASS / FAIL
6. 不给新的学习路线。
```

## Prompt 5 — 路线复盘

```text
现在进入 LearningCI Route Review。

只有本次对话允许调整路线。

依据只能来自：

1. 当前能力树分数
2. 最近 Verification / Retest 结果
3. Reference Project 暴露的问题
4. 前置依赖
5. Parking Lot
6. 实际可用学习时间

请判断：

- 保留节点
- 需要拆小的节点
- 错误前置关系
- 最小新增前置
- 可以延后的节点

禁止因为“热门、更高级、新技术”修改路线。

最终只输出下一阶段冻结路线。
冻结期：14 天。
```
