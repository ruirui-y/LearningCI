# 01. 能力树协议

## 1. 能力树不是课程目录

课程目录按“内容”组织。

能力树按“可验证能力”组织。

例如：

```text
Network
└── TCP
    ├── TCP 字节流与消息边界
    ├── 三次握手
    ├── 序列号与 ACK
    ├── 超时与重传
    ├── 滑动窗口
    ├── 流量控制
    ├── 拥塞控制
    ├── 连接关闭
    ├── TIME_WAIT
    └── TCP 故障诊断
```

如果一个节点无法被独立测试，则继续拆。

## 2. 叶子节点大小

推荐范围：

- 最短：2～4 小时
- 常见：1 个学习日
- 最大：3 天

超过 3 天仍无法验收的节点，需要继续拆分。

## 3. 前置依赖

每个节点必须明确前置节点。

前置节点默认要求 >= 60。

如果学习时发现前置不足：

- 只增加最小必要前置节点
- 不允许因此重新设计整个能力树
- 新增节点必须记录原因

## 4. 节点状态

建议状态：

```text
LOCKED
READY
ACTIVE
TRAINING
VERIFYING
FAILED
PASSED
RETEST_DUE
STABLE
```

含义：

- LOCKED：前置不足
- READY：可学习
- ACTIVE：当前唯一节点
- TRAINING：训练中
- VERIFYING：正式测试中
- FAILED：未达到通过标准
- PASSED：首次通过
- RETEST_DUE：需要 7/30 日复测
- STABLE：延迟复测稳定

## 5. 同时只允许一个 ACTIVE 节点

普通学习日：

> ACTIVE 节点数量必须等于 1。

不能同时：

- 学 TCP
- 看数据库
- 顺便研究 io_uring
- 再看一眼 Raft

其它兴趣统一进入 Parking Lot。

## 6. 大树生成原则

AI 生成能力大树时必须：

1. 先按能力领域分层
2. 再拆到叶子节点
3. 每个叶子节点必须可测试
4. 不按书籍章节组织
5. 不按工具名堆砌
6. 不把“了解”作为能力
7. 建立明确前置依赖
8. 标记核心/重要/外围节点

推荐优先级：

- CORE：目标 >= 80
- IMPORTANT：目标 >= 70
- OPTIONAL：目标 >= 50

## 7. 路线选择原则

学习顺序由以下三项共同决定：

```text
前置依赖
+
当前参考项目需求
+
当前低分能力
```

禁止用以下理由修改路线：

- 更热门
- 更新
- 看起来更高级
- 别人说必须学
- 突然产生兴趣
- 可能有更短路径
