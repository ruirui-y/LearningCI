# 14. 节点细化导入导出流程

## 1. 为什么不是一次性细化全部节点

`plan.json` 已经固定 68 个能力节点，但越远的节点越依赖未来真实源码结构。今天提前精确到半年后的类名、函数名，往往只是伪精确。

因此采用“三节点准备窗口”：

```text
当前未完成主线节点
+ 下一个主线节点
+ 下下个主线节点
```

只有窗口中的节点可以细化。

## 2. 三种执行包状态

```text
草稿（待细化）
    ↓
已审核（可冻结）
    ↓
已冻结
```

- **草稿**：基础编译结果，保证整条路线有内容，但不能正式执行。
- **已审核**：ChatGPT 单节点细化后导回，并通过本地检查。
- **已冻结**：节点走到主线最前方后自动冻结，此后不得覆盖。

## 3. 导出

在“节点准备”页选择可准备节点，点击“导出节点细化包”。ZIP 中包含：

```text
01-节点细化要求.md
02-当前节点定义_禁止修改.json
03-当前节点执行包.json
04-返回文件结构约束.json
05-NebulaRPC总计划.md
06-前置节点学习结果.json
07-项目背景与求职证据.md
08-返回文件说明.txt
```

直接把 ZIP 上传给 ChatGPT 即可，不需要重新解释 LearningCI 方法论。

## 4. ChatGPT 的权限

允许修改：

- 任务组；
- 叶子任务；
- 预计时间；
- 完成条件；
- 证据要求；
- 首次固定试卷。

禁止修改：

- Node ID；
- 路线顺序；
- Stage / Priority / Title；
- 能力定义；
- Must Learn；
- Out Of Scope；
- 项目锚点；
- 评分门槛。

## 5. 导入

ChatGPT 返回一个 JSON 后，在“节点准备”点击“导入 ChatGPT 细化结果”。

程序先：

1. 解析 JSON；
2. 校验 Node / Title；
3. 校验叶子任务字段；
4. 校验固定试卷严格为 100 分；
5. 检查节点是否属于三节点窗口；
6. 暂存到 `待审核/`；
7. 显示任务组与叶子任务数量变化。

只有用户确认后才替换正式执行包，旧版自动备份到：

```text
节点执行包/历史版本/
```

## 6. JSON 为什么仍有少量英文键

`node_id`、`task_groups`、`verification_paper` 等属于机器接口，不要求用户手工编辑。为了让程序结构稳定，它们继续保留固定键名；用户界面、文件名、说明文档和任务正文尽量中文化。
