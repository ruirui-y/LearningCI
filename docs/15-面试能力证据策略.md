# 15. 面试能力证据策略

LearningCI 的最终目的不是“学完”，而是把能力做成面试时可验证的证据。

## 1. 单个核心能力至少要能拿出什么

每个 CORE 能力最终尽量同时具备：

1. **60 秒解释**：不看资料讲清问题与关键机制；
2. **5 分钟深挖**：能沿调用链、状态机或数据路径继续展开；
3. **源码证据**：文件、函数、Git Commit；
4. **正确性证据**：自动测试、故障复现、Sanitizer、抓包等；
5. **性能证据**：如果声称“高性能”，必须有 benchmark / profile 原始数据；
6. **取舍证据**：说明为什么这样设计、替代方案是什么、什么时候会推翻当前方案；
7. **失败证据**：至少保留一些失败实验和修正过程。

只有口头说“我会 epoll / 协程 / RPC”不算强证据。

## 2. 四个项目的证明分工

### DemandStation — 真实生产交付

用于证明：真实客户、部署、维护、稳定运行、MySQL/Redis 依赖、线上问题处置与工程取舍。

面试前应尽量整理匿名证据：部署数量、版本、运行日志、升级记录、故障记录、架构图、Windows 生产选择等。

### MyMuduo — 网络底层能力

用于证明：Reactor、One Loop Per Thread、eventfd、Buffer、TcpClient/TcpConnection 生命周期、定时器、非阻塞 I/O 与性能实验。

任何 QPS/P99 声明都应准备可复现实验，而不是只背 README 数字。

### NebulaRPC — 技术深度主项目

用于证明：Event-Driven Async RPC、RequestId/PendingCall、C++20 coroutine、Exactly-Once Completion、Deadline/Cancel、Multi-Reactor、Backpressure、Reliability、Observability 和性能工程。

这是后续系统类面试的主深挖项目。

### OmniBox — 系统广度

用于证明：Qt6 客户端、UDP 发现、微服务、Protobuf、自研 RPC、文件管理/传输、MySQL 等完整系统协作能力。

不再以“永远加新技术”为目标，而是把现有架构讲透并留下证据。

## 3. 面试表达模板

每个重点项目问题都按这个顺序准备：

```text
问题是什么
→ 当时有哪些真实约束
→ 为什么选这个设计
→ 关键源码在哪里
→ 怎么验证正确性
→ 有什么数据
→ 付出了什么代价
→ 遇到过什么失败/异常
→ 如果规模变化会怎么改
```

## 4. 薪资目标

可以把求职目标设为 15k+，学习和项目证据按更高一档能力强度准备。但具体薪资由城市、公司、岗位、年限、市场和现场面试共同决定，LearningCI 的职责只是尽可能减少“会做但证明不出来”的情况。
