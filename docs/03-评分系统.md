# 03. 评分系统

## 1. 五维评分

### A. 解释 — 15 分

要求：

- 为什么存在
- 解决什么问题
- 不这么做会怎样
- 和相邻概念有什么差别

禁止只背定义。

### B. 预测 — 15 分

给陌生代码、输入或系统场景。

要求在运行前预测结果，并解释依据。

预测是检验“脑内模型”是否正确的重要手段。

### C. 实现 — 25 分

要求：

- 不照抄标准答案
- 独立完成
- 通过自动测试
- 考虑边界条件

### D. 诊断 — 25 分

给一个出问题的系统。

要求：

```text
观察
→ 假设
→ 证据
→ 定位
→ 修复
→ 验证
```

禁止只猜结论。

### E. 迁移 — 20 分

给一个从未做过的新场景。

要求把当前知识用于新设计。

迁移测试是防止“只会做原题”的关键。

---

## 2. 分数含义

- 0～20：听说过
- 20～40：能解释基础概念
- 40～60：能做基础实现
- 60～80：具备基础工程能力，但存在明显短板
- 80～90：工程掌握
- 90～100：能够设计、诊断、优化并解释取舍

## 3. 主线推进与稳定掌握分离

正式 Verification 从 v0.3.11 起不再用 80 分和维度门槛硬卡主线：

```text
总分 >= 70
    → 节点通过，解锁下一节点

总分 >= 节点 target_score（CORE 通常为 80）
并且各维度达到原最低门槛
    → 稳定掌握
```

原维度门槛继续作为薄弱点信号：

```text
解释 >= 10/15
预测 >= 10/15
实现 >= 20/25
诊断 >= 18/25
迁移 >= 14/20
```

维度低于门槛时，Reviewer 应记录到 issues / 复测，而不是在总分已经达到 70 时阻塞主线。

这样把“能继续学习”与“已经稳定掌握”拆开：Recovery Zone 不因边界措辞反复停留，薄弱点仍通过 3D/7D/30D Retest 追踪。

## 4. 禁止平均分掩盖短板

例：

```text
解释 15/15
预测 15/15
实现 25/25
诊断  8/25
迁移  8/20
```

这种情况可以在总分达到 70 后继续主线，但不能标记为“稳定掌握”。

诊断和迁移不足意味着能力仍然不稳定，应进入 issues 与后续复测。

## 5. 评分证据

AI 不允许输出：

> 你表现不错，85 分。

必须输出：

```text
解释 12/15
证据：能够解释字节流，但对 recv 返回条件解释不完整。

预测 11/15
证据：5 道场景预测中错 1 道，错误集中在 EOF 行为。

实现 23/25
证据：18/20 自动测试通过。

诊断 14/25
证据：未识别恶意 length 导致 OOM。

迁移 10/20
证据：新协议设计缺少最大帧限制和版本兼容策略。
```

每一分必须可追溯。

## 6. 延迟复测

首次 85 分不等于稳定掌握。

建议：

- 7 日复测
- 30 日复测

如果：

```text
首次 85
7 日 72
30 日 58
```

长期稳定能力按更低水平处理。

## 7. 三类分数分离

### Capability Score
真正能力。

### Execution Score
是否按计划执行。

### Project Score
真实项目表现。

禁止互相补偿。

连续打卡 100 天不能补偿 TCP 诊断只有 40 分。
