# 小节验收与自动保存

## 1. 为什么取消重复“审计结论”任务

早期 `NRPC-S0-01` 执行包里存在一类重复任务：

```text
逐项阅读 / 回答 / 留源码证据
        ↓
再要求“形成 EventLoop 审计结论”
        ↓
再要求“写一遍审计文档”
```

这会把已经完成的认知工作重复抄写一遍。

v0.3.2 改为：

```text
叶子任务回答 + 源码证据
        ↓
小节 AI 验收
        ↓
通过 / 补强
```

小节验收直接读取当前小节所有叶子任务中的：

- 源码/产物路径；
- 函数/入口；
- 证据备注；
- 完成状态。

用户不需要再写一份小节总结。

## 2. 小节验收评分

每个实际学习小节完成全部必做叶子任务后，可点击：

```text
复制小节验收内容
```

粘贴给 ChatGPT 后，只允许根据现有叶子证据评分：

```text
理解准确度 35
源码证据   30
边界判断   25
覆盖完整度 10
────────────
总分      100
```

本地规则：`>= 80` 才算小节通过。

如果通过后又修改了该小节任意叶子任务的路径、函数、备注或完成状态，旧评分自动标记为“已过期”，必须重新验收。

最终正式 Verification 仍然保留，用来防止“逐项做对但整体模型没有建立”。

## 3. NRPC-S0-01 方法论迁移

`NRPC-S0-01` 的早期执行包已经被冻结并产生学习数据，因此 v0.3.2 不强制覆盖原 JSON，避免破坏历史记录。

程序直接把以下重复任务从手工执行清单中隐藏：

- 各模块的“形成 xxx 审计结论”；
- 最后的审计文档收束/重复归纳任务。

原 41 个任务在用户界面中变为 30 个真实学习叶子任务，并增加 5 个小节 AI 验收。

这属于执行方法修正，不改变 `plan.json` 的学习主路线。

## 4. 自动保存

源码路径、函数入口、证据备注现在采用自动保存：

```text
输入内容
  ↓
450ms 防抖
  ↓
SQLite
```

以下操作前还会强制刷新一次尚未写入的数据：

- 切换到其他叶子任务；
- 开始任务；
- 暂停任务；
- 完成打卡；
- 结束总学习；
- 小节验收；
- 正式 Verification；
- 关闭程序。

因此“暂停任务后刷新 UI 把未保存文字覆盖掉”的旧问题不再存在。

## 5. 后续节点细化规则

Node Compiler 导出的要求已经增加：

- 禁止用“形成结论 / 再写总结 / 再抄到文档”充当叶子任务；
- 每个有实际学习内容的小节应能直接基于叶子证据进行 AI 验收；
- 长期文档如确实需要，应优先由已有证据自动生成，而不是让用户重复抄写。

## v0.3.4 小节验收结果面板

小节评分不再压缩成一行文字。Today 页现在固定展示：

- 理解准确度 / 35
- 源码证据 / 30
- 边界判断 / 25
- 覆盖完整度 / 10
- 编号化问题明细

每个问题单独显示任务 ID、评分维度、短标题和完整说明；问题区拥有独立滚动条。若反馈能够绑定到叶子任务，可直接点击“定位到任务”回到对应任务修改证据。

新格式优先使用 `issues`：

```json
{
  "task_id": "S0-01-EL-02",
  "dimension": "源码证据",
  "title": "调用链证据不完整",
  "detail": "具体说明哪里不完整",
  "severity": "warning"
}
```

历史数据库中只有 `weaknesses` 的评分仍然兼容，LearningCI 会在展示层自动拆成编号问题卡片，不修改历史分数。

## v0.3.9 正式测试修正面板

正式 Verification FAIL 后新增独立修正面板：

- 显示本次未通过的具体机制问题，而不是只显示总分；
- 每条展示题号、维度、原回答、Reviewer 批注与正确机制；
- Reviewer 提供 `related_task_ids` 时可以一键回到原叶子任务证据；
- 点击“重新作答同一冻结试卷”后修正面板继续保留，方便只修错题；
- 历史 v0.3.8 评分没有 `issues` 时，根据失败维度和已保存 evidence 自动生成兼容修正卡片。

因此主流程变为：

```text
正式测试 FAIL
  -> 修正面板定位错误模型
  -> 必要时回看旧叶子证据
  -> 同一冻结试卷重新作答
```
