# 02. 最小能力节点协议

一个叶子节点必须包含以下字段。

## 1. 基本信息

- Node ID
- 名称
- 所属领域
- 优先级
- 前置节点
- 预计训练时间
- 参考项目锚点

## 2. 能力定义

必须使用：

> 在不查资料的情况下，我能够……

例如：

> 在不查资料的情况下，我能够解释 TCP 字节流语义，预测 send/recv 行为，独立实现 Length-Prefix framing，并诊断半包、粘包和恶意长度问题。

## 3. 范围边界

### 必须掌握

明确列出本节点内部内容。

### 暂时不学

明确列出相邻但不属于当前节点的内容。

这个字段用来防止“学着学着不断扩范围”。

## 4. 项目锚点

每个节点必须在真实项目中找到落点：

- 文件
- 模块
- 接口
- 测试
- benchmark
- pcap
- 日志
- 故障复现
- 设计文档

如果完全无法进入项目，必须说明为什么。

## 5. 五维评分

```text
解释      15
预测      15
实现      25
诊断      25
迁移      20
────────────
总分     100
```

## 6. 三套测试

### Training Set

- 可查资料
- 可看答案
- 不计正式成绩
- 用于暴露知识缺口

### Verification Set

- 正式考试
- 禁止提前查看答案
- AI 不得提示关键结论
- 产生正式分数

### Retest Set

- 7 日或 30 日后
- 必须换数据、换代码、换场景
- 用于检测长期掌握

## 7. 完成条件

默认：

- 总分 >= 70：节点 PASSED，允许推进主线
- 总分 >= 节点 target_score（CORE 通常 80）且各维度满足最低门槛：标记为稳定掌握目标
- 有工程产物
- 记录评分证据
- 安排延迟复测

维度短板不再在 70+ 总分时阻塞主线，而是保留为 issues 并通过延迟复测继续验证。
