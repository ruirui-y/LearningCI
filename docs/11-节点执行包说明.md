# 11. 节点执行包：把能力节点变成可打卡关卡

`plan.json` 只负责固定“学什么、按什么顺序学”。真正每天执行的细节保存在：

```text
plans/nebularpc/节点执行包/<Node>.json
```

一个节点执行包包含：

- 任务组；
- 叶子任务；
- 每项任务的目的；
- 操作说明；
- 预计时间；
- 完成条件；
- 工程证据要求；
- 首次固定正式验收试卷。

## 为什么分开

如果把所有细节都写进 `plan.json`，未来源码演进会迫使路线文件频繁变化。现在采用：

```text
plan.json             冻结能力路线
节点执行包/<Node>.json  冻结单节点执行方式
learningci.db         实际学习记录
```

## 状态

```text
草稿（待细化） → 已审核（可冻结） → 已冻结
```

草稿只用于保证整个路线有基础内容。只有经过单节点细化和本地校验的“已审核”执行包才能进入正式学习。

## 首次固定试卷

固定试卷与任务树属于同一个执行包。节点开始第一天就可以预览试卷，但任务未达到最低 Gate 时不能正式提交。

第一次未通过不会换卷，只记录新的作答次数；延迟复测才必须换场景、换题。
